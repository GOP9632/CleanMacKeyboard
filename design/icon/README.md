# Wipe app 圖示

對應 #15。

## 檔案

| 檔案 | 用途 |
|---|---|
| `Wipe.iconset/` | 十個尺寸的 PNG，接進 Xcode Assets 時用這組 |
| `Wipe.icns` | 打包好的 icns，要在 Finder 或 Dock 上直接看效果時用 |
| `contact-sheet.png` | 各尺寸對照表，最下面把 16 與 32 像素放大 8 倍，用來檢查小尺寸的可讀性 |
| `DrawIcon.swift` | 產生器。這組圖示是用程式畫的，要改比例或版面從這裡改，不要去修 PNG。顏色不在這裡，見下面「顏色」 |

## 重新產生

`DrawIcon.swift` 是獨立的 script，不在任何 Xcode target 裡。編譯並執行：

```bash
swiftc -O DrawIcon.swift -o drawicon && ./drawicon "$PWD/out" AL
```

第一個參數是輸出目錄，第二個是鍵帽上的簽名。產出的是 `Wipe.iconset/` 與
`contact-sheet.png`。打包 icns：

```bash
iconutil -c icns out/Wipe.iconset -o out/Wipe.icns
```

## 顏色

青色不寫在產生器裡。執行時直接讀
`Wipe/Resources/Assets.xcassets/Colors/CleaningCyan.colorset/Contents.json`，
淺色值畫在淺色鍵帽表面上的暫停符號，深色值畫在簡化版的深色底上。

**app 改了青色時，重跑一次產生器、把切圖複製回資源目錄就對齊了，不需要改這裡的程式。**
對齊方向是圖示去對齊 app，不是反過來，見 `docs/adr/0003-fixed-accent-colour.md`。

色票讀不到時產生器直接中止，不會退回內建值。那種退路產出的是一組看起來正常、
顏色卻跟 app 對不上的圖，比失敗難發現。

## 分尺寸策略

**16 與 32 像素是獨立繪製的簡化版，不是從大圖縮小的。** 這是 #15 的驗收條件，
不要為了省事直接拿 1024 那張去縮放。三個細節層級：

| 實際像素 | 內容 |
|---|---|
| 16、32 | 只有暫停符號。幾何以整數像素對齊（16 像素時是兩根 4px 寬、9px 高的條，中間 2px 縫），圓角在 16 像素直接歸零，因為 4px 寬的條一圓角就變成圓點 |
| 64 | 鍵帽加暫停符號，砍掉簽名 |
| 128 以上 | 完整版，鍵帽加暫停符號加簽名 |

層級的分界在 `DrawIcon.swift` 的 `detail(forPixelSize:)`。

## 設計決策

- **主體是一顆鍵帽，表面上方刻暫停符號，下方刻簽名 AL。** 這個排版是真實 Mac 鍵帽本來就有的
  結構，主符號在上、次要字符在下。所以簽名不是貼上去的 logo，而是用了鍵帽自己的語言。
- **簽名刻意比暫停符號小。** 暫停符號是辨識主體，簽名是次要字符，兩者不搶同一個視覺層級。
- **暫停符號在每個尺寸都在，位置也固定。** 它的兩根粗直條是極小尺寸下唯一還讀得懂的形狀，
  位置固定讓大小圖之間有視覺連續性。
- **全程扁平風格，鍵帽厚度只用兩層色階，沒有材質光影。** 曾經試過寫實 3D 風格（抹布蓋在鍵盤上），
  失敗原因是織紋、柔光、漸層背景在縮小後全部糊掉，而且多物件的尺度差會讓小的那個在圖示尺寸下消失。
- **這一組就是定案。** #15 原本要的是使用者用 imagegen 產的素材，主題是抹布蓋在鍵盤按鍵上，
  素材規格還寫明無文字。實際交付的是程式畫的鍵帽，而且刻了簽名。這兩處與票上的文字不符，
  使用者在 2026-08-13 確認採用現在這一組。不需要再回頭做 imagegen 那個方向。
- **青色是點綴，不是主色。** 青底的變體已經試過並否決，原因是暫停符號的青色跟底色太接近，
  符號失去對比，整體變成一片青。產生器裡不留那條路，只留採用的深石墨底。

## 已知取捨

`icon_128x128.png`（128 實際像素那張）的簽名接近糊掉的臨界點。實務影響小，因為 Dock 渲染用的是
`icon_128x128@2x.png`（256 像素），簽名在那個尺寸很清楚。若之後判斷 128 那張的簽名是雜訊，
把 `detail(forPixelSize:)` 的 `.mid` 上界從 64 改到 128 即可。

## 已接進 app

`Wipe.iconset/` 的十個 PNG 複製了一份到
`Wipe/Resources/Assets.xcassets/AppIcon.appiconset/`，由 `Config/Wipe.xcconfig` 的
`ASSETCATALOG_COMPILER_APPICON_NAME` 指定採用。

**這裡與資源目錄裡是兩份一樣的檔案。** 改動圖示時要兩邊一起更新：先在這裡重新產生，
再複製過去。這一份是原始素材，那一份是給 Xcode 讀的。

`WipeTests/AppIconTests.swift` 守著四件事：十張切圖一張都不少、七種像素尺寸各有自己的切圖、
16 與 32 像素沒有鍵帽（也就是沒被大圖縮小取代）、以及圖示上的青色與 `CleaningCyan` 是同一個
色值。青色那項會直接讀 app 的色票來比對，所以 app 改了青色而這裡沒跟上時，測試就會紅。

張數與尺寸兩項都要，因為有三種像素尺寸各由兩張切圖供應（32 像素既是 16 點的 2x 也是 32 點的
1x，256 與 512 同理）。少掉其中一張時另一張會頂上，只按尺寸檢查完全看不出來。

青色的門檻用面積比例，不用「有沒有出現過」。實測簡化版佔 22% 到 28%、完整版佔 2.2% 到 2.7%，
門檻分別設在 10% 與 1.5%。用「至少一顆像素」當門檻的話，反鋸齒漏出來的一顆雜點就會讓測試放行。

外觀已在 Dock、Finder 清單檢視、輔助使用授權清單三處實機確認過（2026-08-13）。後兩處顯示的是
32 像素的簡化版，暫停符號在那個尺寸讀得出來。
